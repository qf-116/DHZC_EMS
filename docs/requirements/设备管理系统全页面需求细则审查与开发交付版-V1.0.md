## 0. 审查结论与使用方式

### 0.1 审查结论

当前需求细则**不能直接作为开发合同或生产系统开发基线**。现有文档已经覆盖大量业务目标、主要字段和演示剧本，但存在以下四类问题：

1. **范围口径冲突**：点检、保养、巡检页面在项目状态中明确必须永久保留，但旧的范围外表述仍出现在 `pageSpecs.jsx`；开发人员可能误删菜单、页面或需求说明。
2. **演示能力与生产能力混写**：当前项目是无真实后端、无真实鉴权的前端演示，但“登录锁定、RBAC 生效、自动审计、数据权限过滤、日志保留”等文字容易被理解为已经可验收的生产能力。
3. **关键规则缺少可执行验收条件**：导入导出、权限拦截、日志写入、报表下钻、点检执行结果、报警规则组合条件等存在“页面上有入口、但没有输入/输出/失败处理”的情况。
4. **跨页面事实源不统一**：用户、角色、组织、字典、日志五页目前各自维护局部演示状态；需求却要求角色引用数、组织人员、字典引用、审计日志跨页联动。

### 0.2 本文的处理原则

- 本文**不删除或覆盖**已有文档；作为经过审查后的开发交付版补充基线。
- 本文对冲突规则给出明确裁决；后续开发不得同时保留两套口径。
- “演示版”规则与“生产版”规则分开写。演示版必须能在无后端环境中完成可重复验收；生产版列为后续接口/服务端需求，不能用页面提示代替。
- 点检、保养、巡检页面必须保留。本文中的“承接模块”仅说明数据最终归属，不代表本项目可以删除页面、菜单、路由或细则。
- 本文未规定技术框架、数据库或接口实现方式；开发可自行选择实现方式，但必须满足本文的输入、状态、输出和验收要求。

### 0.3 版本基线

| 项目 | 本文统一口径 |
|---|---|
| 当前交付 | 前端可双击运行的演示版；无真实后端、IoT、WebSocket 和生产鉴权 |
| 演示数据 | 可重置、可重放、跨页面一致；刷新是否保留由页面类型明确规定 |
| 演示时间 | `2026-09-16 16:41:08 +08:00` 为基准；动作按统一演示时钟推进；禁止使用真实当前时间生成业务结果 |
| 设备主键 | `DEV-001..008`；资产编码、监测编码只能通过 `deviceCrosswalk` 映射，不得页面自行猜测 |
| 快照版本 | 以 `src/data/demo/index.js` 当前 `STORE_VERSION` 为准；本文编写时为 10。需求说明中出现的 3、5 均视为过期文字，必须统一修正 |
| 空值 | 未配置、无数据、不可计算、未发生分别保留语义；展示为 `--`，真实数值 0 必须显示 0 |
| 点巡保养 | 页面永久保留；当前为演示交互，完整业务闭环由承接模块负责 |

## 1. P0 决策：开发前必须锁定的统一规则

以下事项如果不先裁决，开发会出现相互矛盾的结果。本文给出默认裁决，产品如需改变，必须形成变更记录后才能开发。

### 1.1 演示版与生产版边界

#### 演示版必须实现

- 页面路由、列表、详情、筛选、弹窗、状态切换和错误提示可操作。
- 同一浏览器会话内，跨页面共享的演示事实必须一致。
- 所有写入动作都必须返回明确结果：成功或失败、失败原因、是否产生事实、关联编号。
- 演示重置后回到固定剧本；不依赖真实日期、真实网络、真实账号。
- 页面必须显示“演示模式”相关提示，但不把演示提示当作业务成功的替代。

#### 生产版必须另行实现

- 服务端鉴权、密码哈希、登录锁定、会话失效、CSRF/审计安全。
- RBAC 路由守卫、操作权限校验、组织数据范围过滤。
- 服务端事务、并发控制、唯一约束、文件存储、导入任务、导出任务。
- 日志不可抵赖、归档、保留周期、权限隔离和真实 IP/设备信息采集。
- SRM/WMS/ERP/IoT/OA 接口及失败重试。

页面文案不得宣称演示版已经完成上述生产能力。演示版可以模拟结果，但必须标注“模拟”或“演示”。

### 1.2 基础配置共享事实源

用户、角色、组织、字典、日志五页必须共享同一份“基础配置演示状态”，而不是每页独立复制种子。

- 初始状态由 `systemConfig.js` 生成。
- 同一会话内：用户新增/编辑/删除、角色绑定、组织改名、字典变更和日志追加立即对其他页面可见。
- 浏览器刷新：按项目统一约定恢复初始种子，或恢复演示快照；不得五个页面各自恢复出不同结果。
- “重置演示”必须同时恢复基础配置和核心业务演示状态。
- 页面内操作必须携带 `actor`、`actionId`、`occurredAt`、`targetType`、`targetId`，以便演示日志追踪。

### 1.3 编码与引用规则

- 设备：只能使用 canonical `deviceId` 关联；资产码/监测码仅用于展示和查询。
- 组织：部门必须有稳定 `orgId`，部门名称和路径是展示字段，不得用可变名称作为唯一主键。
- 用户：`userId`、`account` 分别唯一；账号唯一性默认不区分大小写。
- 角色：`roleId`、`code` 分别唯一；编码创建后不可修改。
- 字典：`typeCode` 全局唯一；同类型 `value` 唯一；历史记录保存 label 快照。
- 业务单据：编号自动生成，不允许页面手填覆盖；重复提交必须通过幂等键返回原结果。

### 1.4 来源设备编码唯一性裁决

现有文档存在三种冲突说法：

- 一处写“被其他设备占用仅提示不拦截”；
- 一处写“来源编码全局唯一/排他”；
- 绑定模板写“平台自动分配全局唯一且不冲突”。

**本文裁决：V1 默认全局排他。** 同一个 IoT 来源设备编码同一时刻只能归属一个系统设备；保存或启用时发现已被其他设备占用，必须阻断并显示占用设备。若未来存在“一源多设备”场景，新增显式字段 `shareable` 和共享授权记录，不能用警告绕过唯一约束。

### 1.5 报警规则基线裁决

- 四类结构化规则（阈值、状态、质量、组合）为当前开发基线。
- 程序比对、备件水位等旧业务规则在列表中可以展示，但必须明确标记为“只读业务规则”或迁移到对应业务模块；不得出现可编辑但保存后静默改变语义的情况。
- 组合规则最少 2 个子条件；删除后低于 2 个必须禁止保存。
- 目标链路统一为“系统设备 → 来源设备 → 指标”，但来源设备不再区分主/子角色。所有文案必须统一为“来源设备”，不得同时使用“子设备/主设备”的旧说法。
- 通知策略页 V1 为策略目录只读页；规则编辑时可对单条规则做临时覆盖，保存完整快照。策略本体编辑、测试发送列为后续生产能力，除非另立需求。
- 规则模板 V1 支持新建、编辑、复制、停用、删除和应用到设备；“只读示例数据”仅指预置模板不可改，不得否定页面的新增/编辑能力。

### 1.6 查询与导出裁决

- 页面输入条件分为“实时筛选”和“点击查询后生效”两类，必须在页面需求中标识，不能一页两种语义混用。
- 导出范围默认等于当前已生效筛选条件，不等于当前未提交的输入框内容。
- 演示版导出至少生成可下载 CSV 或可查看的导出任务记录；只弹 `message.success` 不算导出完成。
- 每个导出任务必须记录：任务号、页面、筛选快照、字段快照、创建时间、创建人、状态（排队/成功/失败）、失败原因、结果条数。
- 空结果导出必须明确提示“当前筛选无数据”，不得生成空文件后提示成功。

## 2. 全局页面开发契约

每个页面必须同时具备以下内容，缺一项即不能标记“需求完成”。

### 2.1 页面说明模板

1. 页面目标与用户角色。
2. 路由、菜单归属、进入条件和返回路径。
3. 数据来源、主键、刷新/查询语义、时间口径。
4. 列表字段、详情字段、字段格式、空值语义。
5. 筛选条件、组合关系、默认值、重置行为。
6. 新增/编辑/状态流转/删除/导入/导出动作。
7. 状态机与每个状态允许的动作。
8. 前置校验、失败提示、是否产生事实、幂等规则。
9. 权限要求和数据范围。
10. 审计日志要求。
11. 空态、无效 ID、无权限、网络/数据异常处理。
12. 至少 3 条 Given/When/Then 验收场景。

### 2.2 通用字段规则

- 编号字段：系统生成、只读、展示完整编号。
- 时间字段：展示时区；演示版使用演示时钟；跨日/跨月归属规则必须写明。
- 数值字段：单位、精度、最小值、最大值、是否允许 0、是否允许小数必须明确。
- 枚举字段：显示 label、存储 value、启用/停用行为和历史快照必须明确。
- 文件字段：文件类型、大小、文件名、是否必传、删除/替换规则、演示版存储方式必须明确。
- 人员字段：同时保存稳定 ID 和展示姓名；姓名变更后历史记录仍按快照展示。

### 2.3 通用状态结果

所有动作统一返回：

```text
ok：是否成功
message：面向用户的结果或失败原因
refs：产生或关联的编号
changed：是否产生业务事实
```

失败时不得部分写入；跨实体动作必须整体成功或整体失败。重复幂等提交应返回第一次成功的 `refs`，并提示“已处理，未重复创建”。

### 2.4 通用权限结果

在演示版中可以用当前登录演示用户模拟权限，但必须定义三层结果：

- 无菜单权限：菜单不显示。
- 有菜单无查看权限：直接访问显示“无权访问”，不得回退到第一条数据。
- 有查看无操作权限：页面可看，操作按钮隐藏或禁用并说明原因。

生产版由服务端再次校验，前端权限不能作为安全边界。

### 2.5 通用审计结果

新增、修改、删除、导入、导出、启停用、发布、回滚、分配权限、重置密码、清空日志、状态流转均须写操作日志。日志至少包含：

```text
logId、occurredAt、actorId、actorName、actorDept、module、actionType、targetType、targetId、before、after、result、failureReason、requestId、costMs
```

敏感字段（密码、完整手机号、令牌）不得写入日志；变更前后只写脱敏摘要。

## 4. 工作台、设备资产与生命周期

### 4.1 工作台 `/`

**目标**：让值班人员在 10 秒内识别待办并进入正确处理页面，不复制完整 KPI 看板。

**七类摘要**：待确认报警、处理中报警、待派工维修、待验收维修、低库存、接入异常、降级设备。每类必须显示数量、前 3 条摘要、统计截止时间和“查看全部”。数量 0 是真实结果，显示 0；数据不可得显示 `--`。

**验收**：

- 点击“待验收”只进入维修列表且预置 `status=待验收`。
- 接入异常按失败/重试中/部分成功汇总，不把未配置设备误计为接入失败。
- 重置演示后七类摘要恢复固定剧本；重置动作不留下业务变更日志，但应写入演示操作记录。

### 4.2 设备台账 `/device-ledger`

**字段**：canonical 编号、资产编码、监测编码、名称、型号、类型、品牌、部门/车间/产线/工位、负责人、生命周期状态、绑定状态、OEE资格、启用日期、购置日期、停用/报废日期。

**筛选**：关键词、类型、车间、生命周期状态、绑定状态、OEE资格。筛选选项来自当前数据；无结果和无数据使用不同空态。

**动作**：新增、编辑、导出、详情、监测详情、联网配置。资产编码和 canonical 编号不可在普通编辑中改；调拨/报废必须走生命周期单据。新增设备必须校验名称、类型、所属组织、负责人；设备编号自动生成且不可重复。

**验收**：跨页跳转必须保留同一 `deviceId`；DEV-008 未绑定时显示未配置，不显示 0；报废归档设备不能新增报警规则、维修工单和绑定。

### 4.3 设备详情与联网 Tab

详情必须分为资产信息、编码映射、绑定概览、接入健康、监控曲线、指标历史、报警、维修、点巡保养关联、生命周期履历、统一业务履历。

- 监控曲线只展示当前启用绑定的数值指标；停用绑定不得继续显示为实时。
- 点检/保养/巡检关联必须按 `deviceId` 或 canonical 映射过滤，再按任务时间倒序；不得用“全局最新任务”套给每台设备。
- 无效设备 ID 显示无对象空态，带返回列表按钮和有效编号说明。
- 联网配置页只读展示协议/网关/IP/端口/点表，不提供编辑；修改入口统一到联网配置总览。

### 4.4 生命周期

#### 设备入账

状态：`试用确认中 → 待设备手续入账 → 设备已入账`；不合格：`试用确认中 → 试用不合格退回 → 重新试用`。同步来源任务不重复录入采购信息；手工补录必须填写来源说明。

- 采购字段：来源、设备名称、型号、数量、品牌、供应商、订单/合同号、发货时间、使用部门、试用负责人、附件。
- 试用字段：结论、意见、问题；不合格时问题必填。
- 入账字段：设备类型、位置、负责人、资产编号、质保期、验收单、档案附件。
- 数量大于 1 时，提交前预览将生成的设备编号；任一台生成失败则整体不入账。

#### 资产变更

类型：调拨、改造、借用、外送；不提供普通移位。状态：待审批、已驳回、已通过、已完成、已取消。通过后必须登记实际执行时间、执行人、前后责任/位置快照。

#### 闲置与再启用

状态：申请、闲置中、复核中、继续闲置、已再启用、转报废。复核结论和意见必填；闲置不删除绑定、报警、运行和历史记录。

#### 报废与归档

状态：申请、技术鉴定中、鉴定通过、鉴定不通过、待财务核销、已核销、已归档。鉴定意见、核销单号是必填门槛；核销前禁止归档，归档后只读且退出 OEE。

## 5. 数据接入与程序比对

### 5.1 联网配置总览

**绑定状态**：未配置、草稿、校验中、校验通过、待生效、已启用、已停用、换绑中。

**编辑流程**：选择系统设备 → 选择来源设备 → 勾选有效指标 → 校验 → 保存版本 → 启用。草稿取消不产生正式版本；刷新/重新进入时草稿是否恢复必须统一为“恢复未提交草稿并标记最后编辑人”，或“退出即丢弃”，不得按页面随机处理。本文选择前者。

**校验**：至少一个来源、至少一个有效指标、指标与来源真实存在、来源编码全局排他、指标类型/版本/量程匹配、同一设备不能有两个启用版本。

**换绑**：必须是真实按钮和动作，不得只有 Tooltip。换绑生成新版本，旧版本保存生效区间；启用新版本成功后旧版本自动结束。换绑失败不得覆盖旧绑定。

**健康任务**：任务类型拉取/补传/补偿；状态成功/部分成功/重试中/失败。重试或补偿必须说明权限、最大次数、幂等键、失败后下一步；同一任务重复触发不得生成重复任务。

### 5.2 绑定模板

模板字段：模板编号、名称、适用设备类型/型号、来源结构、指标及版本、创建/修改人、状态、引用数。预置模板只读；用户创建模板可编辑。

“应用到设备”逐台预览：可创建、已存在跳过、目标无有效绑定阻断、来源编码冲突阻断。批量操作部分成功时逐目标返回结果；批次可重试，已成功目标不得重复创建。

### 5.3 平台指标清单

指标字段：编码、版本、名称、数据类型、单位、精度、有效范围/枚举、同步状态、失效原因、最近同步时间。失效指标不可新绑，但历史快照可查看。

接入任务必须支持按设备、任务类型、状态筛选；任务详情展示失败数、原因、影响范围、责任人、下一步和重试/补偿入口。平台指标目录本身只读。

### 5.4 程序参数比对与处理记录

比对结果：一致、参数不一致、比对失败、不适用。失败不计入不一致；不适用不计入一致率。

参数不一致的处理记录必须有真实创建入口，字段包括：处理结论、措施、处理人、处理时间、影响范围、附件、关联报警/工单。保存后结论不可覆盖，只能追加更正说明。

必须定义“如何恢复一致”：V1 允许登记“已在外部系统完成修改”并发起重新比对；本系统不伪造程序下发。重新比对前后字段快照可追溯；人工确认关闭报警前必须存在有效处理记录并完成复比。

## 6. 实时监测、OEE 与计划停机

### 6.1 实时监控

每台设备必须展示身份、绑定状态、通信健康、运行状态、活动报警数；指标行展示值、质量码、sourceTime、receiveTime、来源编码和指标版本。

- `null`、无样本、OFFLINE、未配置分别解释，不将它们转为 0。
- 断开模式保留最后值但标记“已断开”，不能标记实时。
- 设备筛选和指标筛选不会因刷新丢失；查询条件重置回全部设备。

### 6.2 OEE

公式、分母、时间窗和 blockers 必须全部展示。实时窗口为最近 1 小时；历史为设备×日；日汇总不得用月平均替代。

- 可用率：运行时间 /（负荷时间 - 计划停机时间）。
- 性能率：实际速度 / 理想速度。
- 合格率：良品 / 总产量。
- OEE：三率相乘；任一因子不可计算则 OEE 为 `--` 并列出全部 blockers。
- 计划停机和换模计入分母扣除；故障/维修/待料为损失，不扣计划分母。
- 无生产数据、未配置班次、未配置速度、未启用绑定必须区分原因。

### 6.3 理想速度配置

唯一键为设备+物料；速度必须大于 0，单位为个/小时；保存生成新版本和生效时间。历史日统计使用当日有效版本，修改当前配置不得无提示改写已归档历史口径。

### 6.4 计划停机

字段：设备、分类、计划开始/结束、原因、状态、来源、实际开始/结束、取消原因。状态：待执行、进行中、已结束、已取消。

- 开始必须早于结束；同设备有效事实不得重叠。
- 待执行可删除；进行中/已结束只能取消并填写原因，不能物理删除。
- 维修联动停机由维修动作创建，本页只读展示。
- 取消/编辑后必须触发 OEE 重算并增加重算履历。

## 7. 报警中心、规则、模板与通知

### 7.1 报警事件

状态机：`已触发 → 已确认 → 处理中 → 已恢复待关闭 → 已关闭`。每个状态的进入条件、允许动作、必填字段如下：

| 状态 | 允许动作 | 必填字段/门槛 |
|---|---|---|
| 已触发 | 确认、转维修 | 确认说明；转维修需设备、故障类型 |
| 已确认 | 处置、转维修 | 处置措施、预计完成时间 |
| 处理中 | 更新处置、转维修 | 处置记录；重复转维修幂等 |
| 已恢复待关闭 | 关闭 | 恢复证据、关闭原因；关联维修已验收、关联停机已结束 |
| 已关闭 | 查看 | 不可重开；再次触发生成新事件 |

事件必须冻结规则版本、绑定版本、阈值、触发值和通知快照；规则后来修改不得改变历史解释。重复事件通过 `deviceId+ruleId+ruleVersion+bindingVersion` 去重并累计次数。

### 7.2 报警规则配置

四类规则：

- 阈值：上限、下限、区间外/内；持续时间、恢复阈值、恢复持续时间；阈值必须在指标量程内，恢复方向必须合法。
- 状态：异常枚举和恢复枚举不可重叠，且必须属于指标枚举范围。
- 质量：数据中断、无效率、采集延迟；依据通信健康事实判定，不要求虚构指标值。
- 组合：至少两个子条件，AND/OR；每个子条件独立目标、触发、恢复和有效性。

发布规则：草稿不触发；保存并发布是原子动作；首次为 V1，后续递增；停用不可触发但历史保留；回滚以历史结构化快照发布新版本，不修改旧版本。并发编辑冲突必须提示“当前版本已被他人更新”，不得静默覆盖。

治理参数：重复抑制间隔、风暴窗口/上限/范围/超限动作、静默覆盖。必须保存完整快照并说明最终生效值。

回测：仅当存在真实趋势采样点时显示真实回放结果；没有趋势时显示“无数据，不能完成回测”，不得用近 7 天汇总冒充回测通过。

### 7.3 规则模板与通知策略

- 模板：预置模板只读，用户模板支持编辑和停用；模板不含设备目标；应用模板只生成草稿，不自动发布。
- 通知策略：V1 作为只读策略目录；站内通知为必选渠道。规则保存时固化渠道、接收人、重试、升级和静默配置快照。测试发送不列入 V1，页面不得出现可点击但无行为的按钮。
- 接收人为空时禁止发布；外部渠道失败需记录失败原因和重试次数，不能仅显示成功 Toast。

## 8. 维修与备件

### 8.1 维修报修/主工单

报修字段：设备、故障描述、等级、故障类型、来源、附件、报修人。提交同步生成主工单；设备无效、描述为空、报废设备均拒绝。

工单状态：`待派工 → 已派工 → 维修中 ↔ 挂起 → 待验收 → 已完成`；待派工/已派工/挂起可取消；待验收可返修回维修中。每一转移写时间线、操作人、时间、原因。

- SLA：紧急2小时、严重8小时、一般24小时；明确起算点为创建时间，暂停是否暂停 SLA 必须固定，本文选择“不暂停”。
- 开工创建维修停机；验收通过结束停机；验收返修不得结束停机。
- 领料数量不得超过可用量；同 requestId 不重复扣库存。
- 验收通过需要结论，返修需要意见；返修次数递增，旧时间线保留。

### 8.2 备件

库存行主键为仓库+备件。字段：现存、预留、可用、安全库存、最高库存、单位、水位状态。`可用=现存-预留`；未配置是 `--`，配置后为真实 0 必须显示 0。

入库、出库、退库均写流水，包含前余额、数量、后余额、单据、操作人和 requestId。

- 入库数量必须大于 0。
- 出库数量必须大于 0 且不超过可用量；维修出库必须关联有效工单。
- 退库不超过该出库单未退余量；退库原因必填。
- 负库存禁止产生事实；并发扣减失败需返回最新可用量。
- 低于安全库存提供“去入库”入口，但不自动创建入库单。

## 9. 报表中心统一要求与各报表补充

### 9.1 统一要求

- 所有日期默认锚定 `meta.demoDay=2026-09-16`，禁止使用 `dayjs()` 的真实今天作为演示默认值。
- 日期范围包含起始日和结束日；跨日事实按页面定义的归属时间统计。
- 点击“查询”后形成查询快照；导出使用最近一次查询快照，不使用未提交输入。
- 报表页必须显示数据口径截止时间、数据完整性提示和统计范围。
- 所有报表导出走统一导出任务，不得仅提示成功。

### 9.2 运行时长与设备状态

按设备×日统计运行、待机、故障、离线时长。必须定义总统计时长：状态占比以四类状态时长之和为分母；稼动率以运行/(运行+待机+故障)计算，离线不进稼动率分母。存在状态缺口时显示“数据不完整”，不强行凑 100%。

### 9.3 生产产出

统一字段为总产量、良品、不良品、合格率、运行时长、平均节拍、物料拆分。总产量必须满足 `良品+不良品`；如同时存在 output/processed，必须明确一个为原始计数、一个为加工完成数，并说明报表使用哪个。设备行必须可下钻到物料明细。

### 9.4 MTTR/MTBF

按设备×统计月。MTTR 按开工时间到验收通过时间；跨月工单按开工月归属。MTBF 按有效运行时间/有效故障次数；故障为 0 时显示 `--`。缺开始/验收时间、结束早于开始的异常记录剔除并单列异常数。

### 9.5 综合运行分析

必须选择唯一时间窗；状态、产量、报警、质量、OEE、程序比对都使用同一查询快照，不得一部分使用实时快照、一部分使用日统计。0 是真实值，缺失才是 `--`。

### 9.6 报警统计

按日×设备；事件按触发日归属，跨日未关闭事件只在发生日计数。必须提供报警总数、状态分布、平均确认、平均关闭、重复抑制、升级次数和 SLA 超时数。事件没有完整日期时不能声称支持历史日期筛选，应补齐日期字段或明确仅支持演示日。

### 9.7 数据质量

应采样、实收、有效、缺失、延迟、补传、重复、完整率均可追溯到任务/样本。延迟阈值统一为超过 2 倍采样周期；完整率低只是结果，不得替代质量码判定。DEV-005 必须能跳转 IT-003 失败原因。

### 9.8 程序比对统计

必须展示比对次数、一致、不一致、失败、不适用、已处理/未处理、一致率。一致率分母为有效比对数（总数-失败-不适用）。点击设备行进入程序比对并带设备、日期筛选。

### 9.9 维修统计

必须展示报修数、工单数、状态分布、故障类型、维修总时长、MTTR、一次修复率、返修次数。跨月按开工月，不按创建月替代。所有指标无数据时显示原因。

### 9.10 备件统计

必须展示期初、期间入库、期间出库、期间退库、期末、可用、安全库存、周转天数，并按仓库和业务类型拆分。期初不能用当前库存反推而不说明调整；若使用反推，必须展示勾稽异常。导出包含日期范围和筛选条件。

### 9.11 点巡保养执行统计

三张报表必须定义导出字段、统计范围、任务状态口径、逾期和漏检口径、无匹配计划的处理方式。演示版可导出占位，但必须明确“占位不代表生产导出已完成”。

## 10. 基础配置模块开发交付细则

### 10.1 用户管理 `/system/users`

**字段**：工号、姓名、登录账号、部门、角色、手机号、邮箱、状态、首次登录改密标记、锁定截止时间、最近登录、创建时间、备注。

**校验**：

- 工号自动生成，使用“最大已用序号+1”，删除后不得复用。
- 账号 3–20 位，字母开头；全局唯一且不区分大小写。
- 姓名必填；手机号必填且格式正确；邮箱选填但格式正确。
- 至少一个启用角色；不得绑定停用角色。
- 部门必须为启用节点；停用部门已有人员可继续查看，但不能新增/转入。

**动作**：新增、编辑、重置密码、启用/停用、删除、批量启停、导入、导出。U0001 不得删除或停用，单条和批量均适用。删除是逻辑删除，历史日志保留，账号不可重新占用。

**导入导出**：模板列为姓名、账号、部门编码、角色编码、手机号、邮箱、状态、备注；逐行校验；失败行返回行号、字段、原因；重复账号不得覆盖，整批采用“成功行提交、失败行不提交”并显示汇总。导出默认当前筛选结果，手机号/邮箱按权限脱敏。

**验收**：重复账号、停用部门、停用角色、U0001批量停用均被阻断；编辑账号/工号不可修改；操作产生审计事件；演示重置恢复种子。

### 10.2 角色管理 `/system/roles`

**字段**：角色编号、编码、名称、数据范围、状态、功能权限、操作权限、已分配用户数、备注、创建/更新时间。

**权限模型**：菜单/页面权限与操作权限分离；至少提供查看、新增、编辑、删除、导入、导出、启停、重置密码、分配权限、清空日志等操作点。权限树勾选父节点时是否级联必须明确，本文选择父选中不自动授予所有操作，操作权限需单独确认。

**规则**：编码唯一；R001 系统管理员不可删除、不可停用；停用角色不能新绑定，已绑定用户保留历史引用但权限立即失效；用户数由共享用户事实实时推导，不允许使用静态计数。删除前必须为 0 人且无历史引用阻断要求以“逻辑删除+历史保留”实现。

**验收**：不同角色访问菜单、直达路由和操作按钮结果不同；数据范围“全部/本部门及以下/本部门/仅本人”的过滤样例可验证；权限变更后重新进入页面生效，已打开页面按明确规则刷新。

### 10.3 组织机构 `/system/org`

**字段**：稳定部门 ID、上级 ID、部门名称、完整路径、负责人、电话、排序、状态、备注、创建/更新时间。

**规则**：同级名称唯一；新增/改名均校验；树按同级 sort 升序；编辑移动时同时更新所有子孙的 parentId、路径和用户部门引用；禁止选自身/子孙为上级；根组织不可删除/停用；有子部门或人员不可删除；停用部门不可新增或转入人员。

**快捷新增人员**：与用户管理共用校验和共享事实；至少录姓名、账号、部门、手机号、至少一个角色，密码由用户管理初始化；不允许产生零角色用户。

**验收**：改名、移动、排序、停用父部门、删除有人员部门均有明确结果；人员“含子部门”开关按稳定 ID 过滤，不按名称前缀猜测。

### 10.4 字典管理 `/system/dict`

**类型字段**：类型编码、名称、状态、用途说明、更新时间、更新人。类型编码创建后不可修改。

**项字段**：项 ID、标签、键值、排序、状态、备注、创建/更新时间。标签和值在同类型内唯一；键值默认创建后不可改，如必须修改须作为迁移动作并保留旧值映射。

**引用规则**：业务事实保存 label 快照和 value；停用项不可用于新增，历史显示快照；被引用项不得物理删除，只能停用。类型停用后，该类型下所有项不可在业务新增控件中出现，但历史可查；类型下有项或被引用时不得删除。

**统一消费**：需求必须列出每个字典被哪些页面消费；业务页面不得继续硬编码同一枚举。未接入字典的页面在本期明确标为“待接入”，不能宣称字典已统一。

### 10.5 日志管理 `/system/logs`

**登录日志**：日志号、时间、用户/账号/部门、IP、地点、浏览器、操作系统、结果、失败原因、锁定信息。失败原因不得暴露密码细节。

**操作日志**：日志号、时间、操作人/部门、模块、类型、对象、变更前后摘要、IP、结果、失败原因、耗时、requestId。操作日志必须覆盖本模块和核心业务关键动作。

**筛选**：日期范围、关键词、用户、模块、类型、结果；默认按时间倒序。Tab 失败数按当前筛选还是全量计数需标明，本文选择全量失败数并在提示中说明。

**导出**：导出当前筛选快照；敏感字段脱敏；记录导出日志。演示版生成 CSV/导出任务。

**清空**：仅系统管理员；二次确认、要求输入“清空日志”或明确确认；优先归档而不是物理删除；清空动作自身必须在不可清空的安全审计源中留痕。演示版可清空当前内存列表，但必须提示“不代表生产归档删除”。

**保留**：登录日志至少 180 天，操作日志至少 365 天；归档失败不得静默删除；生产版由后端任务执行，前端只展示策略和结果。

## 11. 点检、保养、巡检页面级补充要求

### 11.1 共同口径

三域页面都必须保留项目、标准、计划、任务、详情、执行、报表页面。数据当前为演示快照，新增/编辑/执行页面内生效；页面必须在显著位置说明“当前演示结果不进入生产闭环”。

- 任务、任务明细必须按任务 ID 隔离，禁止所有任务共用一套全局执行明细。
- 执行记录至少保存执行人 ID、姓名、执行时间、结果、备注、附件/照片（演示可保存文件名）。
- “提交完成”只能在本地演示状态确实更新后提示；不得出现弹窗说已完成而列表仍完全不变。
- 无对象详情必须显示原因、返回列表和下一步动作。
- 数值结果必须校验正常范围；超范围自动标记异常。
- 任何“跳过”必须填写原因；任何“异常”必须选择或填写后续处理方式。

### 11.2 点检

- 项目：名称、类型（单选/数值/文本）、单位、标准范围、默认结果、启用状态。
- 标准：标准编号、名称、版本、关联项目、关联设备/设备类型、启用状态。
- 计划：标准、设备范围、周期、负责人、开始/结束、状态；修改计划只影响未执行任务和后续生成任务，已完成任务冻结。
- 任务：任务号、计划、设备、应检时间、执行人、状态（待执行/进行中/已完成/逾期/逾期完成）。
- 执行：逐项结果正常/异常/未检；数值超范围异常；异常必须说明处理方式；提交需确认执行人。
- 删除计划时，未执行任务如何处理必须明确，本文选择“关联未执行任务一并作废并留痕，已完成任务保留”。

### 11.3 保养

- 项目分组、标准、设备、周期、耗材、预计工时、启停用。
- 执行项结果已做/异常/跳过；跳过原因必填。
- 耗材录入必须有数量、单位、库存校验；若当前演示不接入库存，必须明确“只记录耗材，不扣库存”，不得暗示已出库。
- 工时必须为非负数；报表按任务实耗工时求和，缺失显示原因。

### 11.4 巡检

- 标准包含线路和线路设备顺序；每台设备有位置和项目数。
- 执行页按线路逐设备逐项展示，设备可跳过但必须填写原因。
- 支持合格/不合格、有/无、数值、文本；数值按范围判定。
- 任务状态增加逾期完成；漏检 = 未填写且未合理跳过的明细数；跳过设备数按任务逐条计算，不能复制一个总数到每条计划。

### 11.5 三域报表

必须支持设备/执行人/状态/计划/日期筛选；完成率、异常率、逾期数、漏检数、跳过数、工时等指标定义分母；无匹配任务显示原因。导出字段、文件格式、导出任务和失败行为与第 9 节一致。

## 12. 页面验收场景（开发完成的最低门槛）

### 12.1 基础配置

1. Given 已存在账号 `liming`，When 新增同账号 `LIMING`，Then 阻断并提示账号已存在，不产生用户、不写成功日志。
2. Given 当前选择 U0001，When 单条或批量停用，Then 按钮不可用/动作被拒绝，状态不变。
3. Given 角色 R002 绑定两个用户，When 查看角色列表，Then 已分配用户显示 2；移除一个绑定后显示 1；不是静态种子值。
4. Given 部门存在子部门或人员，When 删除，Then 阻断并列出数量；改名后所有子孙和人员路径同步。
5. Given 字典项已被历史事实引用，When 删除，Then 只能停用；历史记录继续显示原标签。
6. Given 当前登录用户非系统管理员，When 清空日志，Then 无权限且不改变任何日志。
7. Given 当前筛选后有 3 条日志，When 导出，Then 导出任务包含 3 条、筛选快照和脱敏字段，并产生导出审计记录。

### 12.2 数据接入与报警

1. Given 来源编码已被 DEV-001 占用，When 为 DEV-002 保存/启用绑定，Then 阻断并显示占用设备，旧绑定不受影响。
2. Given 报警规则组合只有 1 个子条件，When 保存，Then 阻断并指出至少需要 2 个子条件。
3. Given 已发布规则正在被编辑，When 保存草稿，Then 当前发布版本和历史事件解释不变；发布后才产生新版本。
4. Given 趋势无采样点，When 回测，Then 显示无法回测，不以近 7 天统计冒充成功。
5. Given 报警关联维修尚未验收，When 关闭报警，Then 显示关闭阻塞原因且事件仍为恢复待关闭。

### 12.3 维修与备件

1. Given 工单可用库存为 2，When 出库 3，Then 阻断、不扣库存、不写成功流水。
2. Given 相同 requestId 重复出库，Then 返回同一出库单号，不产生第二条库存事实。
3. Given 待验收工单返修，Then 工单回到维修中、返修次数+1、原验收记录和时间线保留。
4. Given 维修验收通过，Then 关联维修停机结束、工单完成、报警进入恢复流程；三者结果一致。

### 12.4 报表和点巡保养

1. Given 演示日为 2026-09-16，When 点击最近 7 天，Then 计算范围锚定 09-10 至 09-16，不使用真实系统日期。
2. Given 查询后修改输入框但未再次查询，When 导出，Then 导出最近一次查询快照，而不是未提交条件。
3. Given 点检数值超范围，When 提交，Then 明细为异常并要求处理说明。
4. Given 巡检跳过设备未填写原因，When 提交，Then 阻断且不把任务标记完成。
5. Given 无效任务 ID，When 进入详情/执行，Then 显示无对象空态、返回列表和下一步，不展示第一条任务。

## 14. 交付判定

只有同时满足以下条件，才能向开发移交“可直接开发”的版本：

- P0 冲突已按本文裁决，且 `pageSpecs.jsx` 不再保留相反说法。
- 每条路由至少有一个明确页面细则；参数路由、详情、执行、报表不能只复用列表说明。
- 每个可写动作都有字段、校验、状态、失败、不产生事实和审计规则。
- 每个导出/导入入口都有格式、范围、错误报告和任务状态。
- 基础配置五页共享事实源，角色/组织/字典/日志口径可跨页验证。
- 点检、保养、巡检所有页面仍在菜单和路由中，并且各自有页面级验收规则。
- 运行 `npm run build`、`node check-pages.cjs` 后无构建错误、空白页和 JavaScript 错误；涉及状态机的场景通过 reducer/领域规则验证。
